# 备份

Atoll 的备份分两类：**服务数据备份**（每台节点上的 restic，直传 S3 兼容存储）和**中控备份**（中控自己的数据库与密钥，加密打包）。

## 服务数据备份

- **存储**：任何 S3 兼容存储——Cloudflare R2、Backblaze B2、AWS S3、MinIO。在「设置 → 备份存储」填写 endpoint、bucket、前缀（默认 `atoll`）、region（R2 填 `auto`）和访问密钥。所有节点共用这个仓库。
- **仓库密码**：第一次保存时自动生成并**只显示一次**，之后可以在设置里再次查看。没有它就读不出任何快照，请存进密码管理器。
- **数据不经过中控**：每台节点的 agent 在本地用容器跑 `restic`，直接和存储桶通信。
- **内容**：数据库模板（PostgreSQL、MySQL、MongoDB、Redis）用数据库自带工具做逻辑导出；其他服务对卷目录做快照。数据库也可以额外包含卷。
- **调度在节点上**：agent 保存了本机所有策略，自己按计划执行，**中控离线时备份照常进行**，结果在重连后补报。
- **策略**：每个服务一条策略，cron 表达式（默认每天 03:00）加时区；保留数量按天 / 周 / 月（默认 7 / 4 / 6）。

## 恢复

- **原地恢复**：停掉容器，把当前卷目录挪到一旁作为恢复前副本，再写回备份数据；失败会自动放回原数据并重启容器。
- **恢复到另一台机器（灾难恢复）**：只在项目原来的机器**离线**时允许，整个项目会被重新分配到目标机器，并恢复这一个服务的数据、同步入口和 DNS。原机器还在线时请用迁移功能。
- 通过 CLI / MCP 发起的恢复需要 `restore` 权限；开启了「需要面板审批」的令牌会先进入审批。

## 备份校验

备份只有能恢复才算数，所以 Atoll 会定期验证（同样由节点执行，中控离线也照常）：

- **仓库检查**（每周）：`restic check --read-data-subset`，默认抽查 5% 数据，由一台在线节点负责。
- **恢复演练**（每月）：把每个启用策略的最新快照恢复到临时目录或临时容器（无网络、不发布端口），检查文件或数据库表能读出来，结束后清理，不碰正在运行的服务。

调度时间可以在设置里改为固定 cron 或关闭。

## 中控备份

中控每天自动做一份加密的中控备份（数据库快照 + `master.key` 等），本地保留最近 3 份；配置了备份存储时也上传到同一个桶的 `<前缀>/control/` 下。导出、恢复和迁移中控的完整步骤见[中控运维](control.md)；Docker 部署见[用 Docker 安装中控 → 备份与恢复](install-docker.md#备份与恢复)。

## 命令行

```sh
atoll backup list SERVICE
atoll backup run SERVICE
atoll backup restore SNAPSHOT [--to SERVER]
atoll backup policy SERVICE --enable --schedule "0 3 * * *" --keep-daily 7
atoll backup verify [SERVICE]
```

接口和限制（如 PostgreSQL 恢复不中断单条语句错误、Redis 按 RDB 处理）见 [API 文档 → Backups](api.md#backups)。
