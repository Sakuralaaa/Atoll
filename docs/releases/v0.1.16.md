# Atoll v0.1.16

修 Zeabur 本机接管（导入）在一台真实机器上遇到的几个问题。

- **容器用户**：服务新增 `user` 字段（等同 `docker run --user`，`uid`、`uid:gid` 或用户名，留空用镜像自带的 USER）。Zeabur 几乎所有 Pod 都以 root（`runAsUser: 0`）运行，而不少镜像声明了非 root 用户；导入后按镜像用户运行会读不了 root 拥有、权限 600 的数据文件。现在导入会照搬 Pod 的 `runAsUser`/`runAsGroup`。
- **PostgreSQL 角色和密码**：迁移数据库前先用 `pg_dumpall --roles-only` 复制角色。之前只导数据库本身，指向应用角色的 RLS 策略和授权会恢复失败；应用连接用的角色密码（常常不是镜像的 `POSTGRES_PASSWORD`，那个只在初始化时生效）也会丢，应用登录失败。恢复时不再丢弃授权（去掉 `--no-acl`）。
- **TimescaleDB**：检测到 `timescaledb` 扩展的数据库改为在新库里用 `timescaledb_pre_restore()` / `timescaledb_post_restore()` 恢复，再以行数校验数据。目标镜像需要和 Zeabur 上的 TimescaleDB 版本一致，建议把镜像固定到 Zeabur 正在运行的 digest。
- **演练尊重固定的镜像**：把导入的服务 PATCH 成同一仓库的 `repo@sha256:…` 后，演练会拉这个 digest，而不是再拉一次原来的浮动标签（用于标签已经更新到一个起不来的版本时，保留 Zeabur 上跑着的那一版）。

## 需要注意

- 有数据库迁移（0015：`services.run_as`），中控和 agent 都要升级；只做 Zeabur 接管的节点必须升级 agent，其余节点可以不升。

## 升级

「中控 → 更新」或 `install-server.sh --version v0.1.16`；节点在「服务器」页一键升级 agent。
