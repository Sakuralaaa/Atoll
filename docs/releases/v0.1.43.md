# v0.1.43

## 卷的属主自动处理

- 以非 root 用户运行的镜像（Dockerfile 里写了 `USER`，或服务设置了运行用户），现在可以直接写挂载卷了。以前 Atoll 用 root 创建卷目录，这类镜像写数据时会报 `EACCES`，只能手动 chown，或通过 API 给卷设 `owner`。
- 每次部署、启动、重启时，以及容器反复重启期间，agent 会把卷目录交给容器实际运行的用户。判断顺序：卷的 `owner`，其次是服务的运行用户，最后是镜像的 `USER`。如果是用户名，就从镜像自带的 `/etc/passwd` 和 `/etc/group` 解析成 uid 和 gid。
- 只在目录为空，或里面的文件全部属于 root 时才修改，这样不会动到应用自己管理过属主的数据。以 root 启动、再自行降权的镜像（postgres、redis 等）不受影响。接管的宿主机目录也不受影响。
- 旧版本建坏的卷：升级 agent 后，在面板里重启或重新部署一次即可修复。
- 查询失败只记录日志，不会让部署失败。

## 升级

只涉及 agent。升级中控后，在「服务器」页点「全部升级」，或运行 `atoll servers upgrade-agent --all`。然后把之前写不进卷的服务重启一次。
