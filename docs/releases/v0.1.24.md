# Atoll v0.1.24

多个根域名：设置里可以配置一组根域名，每个项目选自己的默认根域名，绑定域名时挑后缀。

- 设置 → 根域名：添加 / 移除 / 设为默认。每个根域名自动按后缀匹配 Cloudflare Zone（最长的优先，比如 `apps.example.org` 优先用同名 Zone，没有就用 `example.org`），并显示证书状态。
- 证书：新根域名默认「自动」，用 Cloudflare API 令牌签发 Origin CA 证书（覆盖 `example.net` 和 `*.example.net`，15 年）；令牌没有权限或签发失败时改用 ACME，并在列表里写明原因。也可以选「ACME」或「跟随全局 HTTPS 设置」。每台服务器的 atoll-caddy 按 SNI 选证书。
- 项目设置 → 默认根域名：这个项目新绑定的域名默认建在它下面，已有域名不变。
- 绑定域名：填前缀（`blog`、`api.v2`，留空为根域名本身），在下拉里选根域名；「完整域名…」可填其他域名。
- DNS 记录按域名所属的根域名写到对应的 Zone。
- API：`GET/POST /root-domains`、`PATCH/DELETE /root-domains/{name}`、`POST /root-domains/{name}/refresh`；Project 新增 `root_domain`；绑定域名可带 `root_domain`；`settings.base_domain` 仍然有效，表示默认根域名。详见 docs/api.md「Root domains」。

## 需要注意

- **中控和所有节点都要升级。** 旧版 agent 不认识按根域名的证书，会对所有域名出示全局证书，新根域名下的站点会证书不匹配。
- **新根域名在 Cloudflare 的 SSL/TLS 模式请设为 Full (strict)。** Flexible 模式下 Cloudflare 用 HTTP 回源，Caddy 会跳转到 HTTPS，浏览器陷入重定向循环。
- 自动签 Origin 证书需要给 Cloudflare API 令牌加上 Zone 权限「SSL and Certificates: Edit」（原有的「DNS: Edit」保留）。不加也能用，只是走 ACME；ACME 根域名下有站点时，节点 80/443 的「只放行 Cloudflare」防火墙会放开，让证书机构能访问。
- 只有一个根域名时行为与 v0.1.23 完全一致：升级时原来的主域名迁成默认根域名，证书模式「跟随全局」，推给节点的配置逐字节不变（有测试覆盖）。
- 新迁移 0019（`root_domains` 表、`projects.root_domain`），升级时自动执行。

## 升级

1. 「中控 → 更新」，或重跑 `install-server.sh --version v0.1.24`。
2. 「服务器」页升级每台节点的 agent（批量升级即可）。
3. 添加新根域名前，先在 Cloudflare 把它的 SSL/TLS 模式设为 Full (strict)。
