# Atoll v0.1.9

## 新功能

- **无卷服务零停机部署**：没有挂卷、也不占用宿主机端口的服务改为先起新容器，过健康检查和观察期后再切流量、停旧容器；失败时旧容器继续服务。有卷或有宿主机端口的服务仍是先停旧再起新。部署事件里会写明用的是哪种方式。
- **默认资源上限**：「设置 → 默认资源上限」，新建服务（镜像、模板、源码构建、导入、Zeabur 接管、CLI）没填上限时套用，默认内存 1024 MB、CPU 不限，0 表示不限。已有服务不变，状态页「未限制」旁可一键套用默认值。
- **备份校验**：每周 `restic check --read-data-subset`（默认 5%，同一仓库只由一台节点跑），每月对每个备份策略做恢复演练（卷恢复到临时目录、数据库导出导入临时容器并查询，完成后清理）。由节点本地调度，中控离线照常执行；失败生成「备份校验失败」异常并通知。备份页显示最近结果，可「立即校验」「立即演练」；CLI `atoll backup verify|check|drill`，MCP `backup_verify` / `backup_check` / `backup_drill`。
- **筛选标签**：项目列表、项目内服务列表、服务器列表可按 异常 / 运行中 / 已停止 / 部署中、在线 / 离线 / 异常 筛选，带计数，选择记在 URL `?filter=` 里。
- **导出 .env**：服务环境变量页「导出 .env」，可复制或下载，机密变量默认不导出；CLI `atoll env export -s SERVICE [-o FILE] [--include-secrets]`，输出可被 `atoll env import` 原样读回。
- **前端冒烟测试**：CI 用 Playwright 在 demo 模式下打开各页面、点击按钮，防止「点了没反应」回归。

## 需要注意

- **API 默认值变化**：创建服务时不传 `mem_limit_mb` 现在会得到默认上限（1024 MB），要明确不限请传 `-1`。
- **Zeabur 接管**：原来不限内存的大服务接管后会被限到默认上限，可能被 OOM 重启。导入计划里有提示；接管大数据库前请先调高或把默认值改成 0。
- **读取机密值的权限**：`GET /services/{id}/env?reveal=1` 现在也允许带 `exec` 权限的 API token（能在容器里执行命令本来就能读到环境变量）。迁移 0010 之前创建、带 `deploy` 权限的 token 保留了 `exec`，因此也能读取。每次读取都记审计 `env.reveal`。
- 恢复演练用服务自己的镜像起无网络的临时容器，镜像需在该节点上，并需要足够磁盘空间。

## 从 v0.1.8 升级

1. **中控**：先在「中控 → 备份」做一次备份，然后「中控 → 更新」，或重跑 `install-server.sh --version v0.1.9`。
2. **节点**：「服务器」页顶部「全部升级」。

有一个数据库迁移（0014，新增 `backup_verifications` 表）。回退到 v0.1.8 前请先恢复升级前的中控备份。
