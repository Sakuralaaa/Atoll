# Atoll v0.1.25

**接管自己用 Docker 启动的容器**：服务器上用 `docker run` 或 `docker compose` 起的容器，可以原地交给 Atoll 管理——同样的宿主机端口，绑定目录和数据卷原地挂载（不复制数据），旧容器、镜像和卷永远保留，随时回滚。说明见 [docs/adopt-docker.md](../adopt-docker.md)。

> ⚠️ 这个功能**还没有在真实的 Docker 主机上完整验证过**（单元测试和模拟 agent 的集成测试已覆盖）。第一次使用请挑不重要的项目，先演练再切换。

- **扫描**：agent 列出不归 Atoll 管的容器，按 compose 项目分组（单独容器各成一组），提取镜像（固定 digest）、环境变量、命令、用户、端口（含绑定 IP）、挂载、重启策略和资源限制。
- **风险分级**：host 网络、privileged、挂载 Docker socket、devices、cap_add、关闭安全配置、宿主机命名空间、80/443 等情况标为「需手动处理」，写明原因，不会自动接管。
- **演练**：Atoll 副本在旧容器旁边启动，不发布端口，可写数据用临时空目录（绝不和旧容器同时写同一份数据），健康后停掉；有内存检查。
- **切换**：旧容器重启策略改为 `no` 后停止（不删除），Atoll 服务用同样的端口和原地挂载的数据启动；失败自动回滚。**回滚**：重新启动旧容器并恢复重启策略。
- CLI `atoll docker scan|import|rehearse|cutover|rollback|status`，MCP 工具 `docker_scan`、`docker_adopt`、`docker_rehearse`、`docker_cutover`、`docker_rollback`，面板 `/import/docker`（迁移页和服务器设置里有入口）。
- 服务规格新增 `volumes[].host_path` / `read_only` 和 `ports[].host_ip`。`host_path` 只能由接管设置，API 不能新增或修改；这类服务不参与 Atoll 的备份、恢复和迁移（会明确报错）。

## 安全

- **CVE-2026-98432**：Go 1.24 起 Linux 上监听默认用 MPTCP，公开的远程 root 利用需要 MPTCP 监听。所有 Atoll 程序现在默认关闭 MPTCP（`go.mod` 里 `godebug multipathtcp=0`；如需打开设 `GODEBUG=multipathtcp=2`）。根本修复仍是升级内核；打补丁前可先 `sysctl -w net.mptcp.enabled=0`。

## 需要注意

- **没有数据库迁移**（新字段存在已有的 JSON 列里）。
- **已经接管了容器的服务器不要把 agent 降级到 v0.1.25 以前的版本**：旧 agent 不认识 `host_path` / `host_ip`，会把服务挂到空的 Atoll 卷目录上，并把只绑定在 127.0.0.1 的端口发布到所有网卡。
- 切换之后不要再对那个 compose 项目运行 `docker compose up`，否则旧容器会和 Atoll 的服务抢端口。

## 升级

「中控 → 更新」，或重跑 `install-server.sh --version v0.1.25`。要接管容器的服务器需要把 agent 升级到 v0.1.25（面板里一键升级）。
