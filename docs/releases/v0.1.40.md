# Atoll v0.1.40

## 修复

- **手动「检查更新」不再拿到缓存的旧 digest**：之前镜像 digest 和 tag 列表走 registry 客户端缓存（digest 10 分钟、tag 列表 30 分钟）。新镜像推送前检查过一次，推送后 10 分钟内再点检查仍是旧 digest，不出现更新按钮（例如 `ghcr.io/sakuralaaa/blog:latest`）。现在用户手动触发的检查（面板按钮、CLI `atoll updates --check`、MCP 新工具 `update_check`，都走 `POST /services/{id}/image-update/check`）会跳过缓存直接问 registry，并把新结果写回缓存。点「更新」部署时也会重新取 digest。后台定时检查仍走缓存。
- **限流原因写清楚**：registry 返回 429 时，手动检查同样遵守退避，不会在退避期内发请求。服务卡片上会显示「registry … is rate limiting requests (HTTP 429)」以及下次可请求的 UTC 时间。

## 新增

- MCP 工具 `update_check`（需 `deploy` 权限）：立即检查某个服务的镜像更新，此前 MCP 只有只读的 `update_list`。

## 升级

只需升级中控。无数据库迁移。用 MCP 的话，本地 `atoll` CLI 也升级到 v0.1.40 才有 `update_check`。
