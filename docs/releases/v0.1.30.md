# v0.1.30

修复 v0.1.29 中控与节点连接反复断开的问题，并支持拖动调整项目里服务的顺序。

## 修复：v0.1.29 中控连接不稳定

v0.1.29 中控把 Agent 发来的帧改到每连接一个后台 goroutine 处理，并在 ping 失败时用 `logs.close` 消息兜底测延迟。在真实环境里这导致 Agent 连接被反复断开：所有服务器延迟显示「—」，部署失败并报 `apply: agent disconnected`。回退到 v0.1.28 即恢复。

这一版：

- 中控与 Agent 的连接处理**恢复为 v0.1.28 的写法**（读循环里按顺序同步处理帧），去掉帧工作 goroutine 和 `logs.close` 兜底测量。
- 保留 v0.1.29 的失败记录：ping 超时（20 秒）仍会记下原因，界面显示红色「超时」，悬停可看错误；失败**不会**断开连接。`latency` 字段里的 `failures`、`failures_total`、`last_error`、`last_attempt` 保留，`method` 现在总是 `ping`。
- v0.1.29 的全部界面修正保留。

## 新功能：拖动调整服务顺序

- 项目页左侧「服务」列表可以拖动排序：鼠标悬停时行首出现拖动把手，平板 / 手机上把手常驻，按住拖动即可（基于 pointer 事件，触屏可用）。
- 顺序按项目保存在中控，所有设备和账号看到的顺序一致；未排过的服务排在后面，按名称排序。按状态筛选时不能拖动。
- 新接口 `PUT /api/v1/projects/{id}/service-order`，请求体 `{"services": ["svc_…", …]}`（从前到后），需要部署权限；不属于该项目或重复的 id 返回 400。迁移 `0021_service_position.sql` 给 services 表加 `position` 列。

## 升级

只需升级中控，节点不用动。**如果你已经在 v0.1.29 并回退到 v0.1.28，可以直接升级到 v0.1.30**；升级前照例先备份中控。
