# Atoll v0.1.38

## 修复与改进

- **CLIProxyAPI 配置可在面板里修改并保留**：之前 `config.yaml` 以只读方式挂载，在 CPA 管理面板里改的 API Key、提供商等重新部署后丢失。现在：
  - 初始配置改为只读的 `/CLIProxyAPI/config.seed.yaml`，首次启动时复制到持久卷 `config`（`/CLIProxyAPI/conf/config.yaml`），CPA 以 `-config /CLIProxyAPI/conf/config.yaml` 运行；
  - 之后在 CPA 管理面板或 Atoll「文件」页修改都会保留，重新部署也不会覆盖。管理密钥仍来自环境变量 `MANAGEMENT_PASSWORD`。
- **创建应用时可绑定第二个域名**：模板服务可声明一个可选域名（`domain: true`）。CLIProxyAPI 创建时多一个「API 域名（可选）」，直接绑定到 cli-proxy-api 的 `api` 端口；长请求建议灰云。
  - API：`POST /api/v1/app-templates/{id}` 新增 `domains: {服务名: 域名}`，结果里的 `extra_domains` / `domain_errors`
- **非 root 镜像的卷权限**：卷新增 `owner`（`uid` 或 `uid:gid`），节点在卷目录为空时把它交给该用户。n8n 模板的数据卷设为 `1000:1000`，修复 n8n 因 `/home/node/.n8n` 归 root 无法写入而启动失败。

## 升级

升级中控和所有节点（卷 `owner` 由节点执行）。无数据库迁移。

## 注意

- **v0.1.37 部署的 CLIProxyAPI 不会自动变更**：已有项目仍是只读的 `/CLIProxyAPI/config.yaml`。二选一：
  - 从模板重新创建（需重新登录各账号，或先在「文件」页备份 `auths` 卷里的认证文件）；
  - 或手动迁移：给 cli-proxy-api 加卷 `config` → `/CLIProxyAPI/conf`，把配置文件路径改成 `/CLIProxyAPI/config.seed.yaml`，启动命令设为 `sh -c '[ -f /CLIProxyAPI/conf/config.yaml ] || cp /CLIProxyAPI/config.seed.yaml /CLIProxyAPI/conf/config.yaml; exec /CLIProxyAPI/CLIProxyAPI -config /CLIProxyAPI/conf/config.yaml'`，然后重新部署。
- 已部署且启动失败的 n8n：升级节点后重新部署即可（卷目录为空时才会改属主）；卷里已有文件的不会被改动。
- 新的 CPA 启动方式和 n8n 卷属主尚未在真机上验证，如遇问题请提 issue。
