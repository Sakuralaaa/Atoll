## 从 v0.1.4 升级

**先备份**：`sudo cp -a /var/lib/atoll /var/lib/atoll.bak-v0.1.4`（中控上执行，业务容器不受影响）。

1. **中控**：用当初安装时的同一组参数重跑安装脚本（v0.1.4 还没有面板内更新，从 v0.1.5 起可以在面板「中控 → 更新」里升级）：
   ```bash
   curl -fsSL https://raw.githubusercontent.com/Sakuralaaa/Atoll/main/install/install-server.sh \
     | sudo sh -s -- --domain panel.example.com --version v0.1.5
   ```
   数据库迁移 0008–0011 在启动时自动执行。中控重启的几秒内面板不可用，业务流量不受影响，agent 会自动重连。
2. **节点**：v0.1.4 的 agent 能直接连新中控，现有容器不会被重建。要用源码构建、构建资源限制等新功能，在每台节点上重跑：
   ```bash
   curl -fsSL https://raw.githubusercontent.com/Sakuralaaa/Atoll/main/install/install-agent.sh \
     | sudo sh -s -- --server https://panel.example.com
   ```
   已加入的节点会跳过加入步骤，不需要 token。

**行为变化**
- API token：原来有 `deploy` 权限的 token 自动获得新的 `exec` 权限（在容器里执行命令）；之后新建的 token 需要单独勾选 `exec`。
- 会话：7 天不用会自动失效（从升级时开始计算），最长仍是 30 天。
- 端口：服务的 `public_port` 不能再用 22、7301、41641、41000–41999。已有服务原来的设置保留。
- 源码构建：首次构建会拉取 `moby/buildkit` 镜像，构建默认有内存上限和磁盘检查，可在节点的 `/etc/atoll/agent.env` 调整（见 README）。

## 主要变化
- 安全：exec 独立权限；保留端口；面板 CSP 和 HSTS；agent 只用 `Authorization` 头认证；webhook 按投递 ID 去重；会话空闲过期；安装脚本校验 SHA256SUMS；添加节点命令带 agent 二进制哈希；Release 带构建来源证明。
- 多机：构建资源限制和磁盘保护；SQLite 只读连接池。
- 中控管理：状态、日志、审计、加密备份、面板内自更新和回滚、一条命令迁移中控。
- 源码构建：GitHub 仓库构建和 push webhook 自动部署（面板、CLI、MCP）。
- 用 Go 1.26.10 构建（v0.1.4 及之前用的是 1.26.0，带有已修复的标准库漏洞）。
- 维护：拆分大文件，重写 README，新增 CONTRIBUTING 和 PR 模板，CI 增加 `-race`、gofmt、oxlint、govulncheck。
